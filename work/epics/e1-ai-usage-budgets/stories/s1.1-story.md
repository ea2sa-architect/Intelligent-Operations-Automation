# Story: Budget schema + spend-check

## User Story
As a governance admin,
I want AI inference spend computed against a definable budget per scope (model/user/service/workflow),
so that later stories (enforcement, escalation, admin UI) have a real, tested foundation to build on instead of inventing spend logic ad hoc.

## Acceptance Criteria

### Scenario: spend is under the limit
```gherkin
Given a usage_budgets row scoped to user_id "team-x", limit_usd 100, period "monthly"
And inference_requests for user_id "team-x" this period sum to estimated_cost_usd = 40
When checkBudget({ scopeType: 'user_id', scopeValue: 'team-x' }) is called
Then it returns { status: 'ok', budget: <the row>, spent_usd: 40, limit_usd: 100 }
```

### Scenario: spend crosses the warn threshold (80%)
```gherkin
Given the same budget, limit_usd 100
And summed spend for this period = 85
When checkBudget(...) is called
Then it returns { status: 'warn', spent_usd: 85, limit_usd: 100 }
```

### Scenario: spend exceeds the limit
```gherkin
Given the same budget, limit_usd 100
And summed spend for this period = 120
When checkBudget(...) is called
Then it returns { status: 'breach', spent_usd: 120, limit_usd: 100 }
```

### Scenario: no budget bound to this scope
```gherkin
Given no usage_budgets row exists for user_id "team-y"
When checkBudget({ scopeType: 'user_id', scopeValue: 'team-y' }) is called
Then it returns { status: 'ok', budget: null, spent_usd: 0, limit_usd: null }
```
Budgets are opt-in (design.md) — an unscoped/unbudgeted request is never blocked by this story's logic.

### Scenario: period boundary — spend from a prior period doesn't count
```gherkin
Given a monthly budget, limit_usd 100
And inference_requests for this scope: 90 spent last month, 10 spent this month
When checkBudget(...) is called
Then it returns { status: 'ok', spent_usd: 10, limit_usd: 100 }
```

## Examples (Specification by Example)

| Input (spend / limit) | Action | Expected `status` |
|---|---|---|
| 40 / 100 | `checkBudget` | `ok` |
| 85 / 100 | `checkBudget` | `warn` |
| 100 / 100 | `checkBudget` | `breach` |
| 120 / 100 | `checkBudget` | `breach` |
| — / no budget row | `checkBudget` | `ok` (budget: null) |

## Notes

Foundation story only — this does **not** wire `checkBudget()` into
`inference.js`'s routes (S1.2), fire escalations (S1.3), or add any UI
(S1.4). See `work/epics/e1-ai-usage-budgets/design.md` — Key Contracts for
the exact `checkBudget()` signature and `usage_budgets` shape this story
must produce, since S1.4's admin page will be built against that contract
before S1.2/S1.3 exist (epic scope.md — Sequencing Risks).

Warn threshold is 80% of `limit_usd`, breach is ≥100% — fixed values for
this story; per-budget-configurable thresholds are not in scope (not
mentioned in epic scope.md, would be a scope addition if wanted later).
