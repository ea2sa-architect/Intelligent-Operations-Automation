# Story: Enforcement wiring

## User Story
As a governance admin,
I want a bound budget to actually gate new inference requests,
so that a `hard`-mode budget genuinely stops overspend, not just measures it after the fact.

## Acceptance Criteria

### Scenario: hard-mode budget already breached blocks the new request
```gherkin
Given a usage_budgets row scoped to user_id "team-x", mode "hard", already in breach
When POST /inference-service/ (create inference request) is called with user_id "team-x"
Then it returns 403 with { error: 'Blocked by usage budget', budget: {...} }
And no inference_requests row is created
```

### Scenario: soft-mode budget already breached warns but proceeds
```gherkin
Given the same budget, mode "soft"
When POST / is called with user_id "team-x"
Then it returns 202 (request created), with header X-IOA-Budget-Warning set
```

### Scenario: no budget bound — unaffected
```gherkin
Given no usage_budgets row for this scope
When POST / is called
Then it behaves exactly as before this story (no new header, no block)
```

### Scenario: budget check only gates on historical spend, not this request's own (unknown) cost
```gherkin
Given a budget with spend currently under the limit
When POST / is called (a request whose own cost isn't known until completion)
Then the gate passes — this story cannot and does not predict the new request's cost
```

## Examples

| scope spend state | budget mode | Result |
|---|---|---|
| breached | hard | 403, no row created |
| breached | soft | 202, `X-IOA-Budget-Warning` header, row created |
| under limit | either | 202, no header |
| no budget bound | — | 202, no header (unchanged from today) |

## Notes

Scoped to `POST /` only — see `design.md`'s "POST / insertion point". The
`PUT /:id` completion-time check (where a request's *own* cost becomes
knowable and a fresh breach can be detected) is **S1.3**'s territory, since
that's also where escalation fires. This story does not touch `PUT /:id`
and does not call `escalation-client.js` (doesn't exist until S1.3).
