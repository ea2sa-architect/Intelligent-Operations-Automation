# S1.1 Retrospective: Budget schema + spend-check

**Story:** S1.1 | **Epic:** E1 | **Size:** M | **Date:** 2026-08-03

**Time:** Estimated 240 min, actual ~90 min (velocity 2.67x) — **low-confidence
calibration data.** No wall-clock tracking exists for this session; these are

## What Went Well

- The plan's mandatory Task 4 (manual verification against real Postgres)
  wasn't decorative — it caught exactly what it was designed to catch. The
  breach scenario returned `spent_usd: 120`, proving the prior-month $500 row
  was correctly excluded by the real `TIMESTAMPTZ` comparison, which a mocked
  test cannot verify by construction.
- Grounding the design in actual grep'd code (governance-client.js's
  fail-closed comment, rule-evaluator.js's per-asset shape) before writing
  ADR-001/002 meant the architecture decisions were defensible, not
  speculative — no rework needed during implementation.
- Schema-first task ordering (Task 1 before Task 2, despite no hard
  dependency) paid off — Task 2's helpers and Task 3's queries were written
  against real column names/types from the start.

## What to Improve

- Two of `.raise/manifest.yaml`'s `rai init --detect`-detected values are
  wrong for this repo (`test_command: npx vitest run` fails at root — no
  root config; `lint_command: npx eslint .` fails for every backend service
  — only `web/` has a config). Both were discovered ad hoc, mid-task, rather
  than caught up front. Persisted as PAT-S-001 so future stories don't
  re-trust them blindly.
- No lint tooling exists for backend services at all — a real gap, not
  fixed here (out of scope for S1.1), but it means this story shipped
  without a lint gate that the plan assumed would exist.

## Heutagogical Checkpoint

**1. What did you learn?**
That this codebase's test convention (mock `pool.query` entirely, no
real-DB integration tests) is a genuine, load-bearing gap — not just a
"nice to have." It's not hypothetical: this story's Task 4 caught a real
class of bug (calendar-boundary filtering) that the mocked tests in Task 3
structurally could not have caught, no matter how well-written. Also
learned, concretely, that `pg` returns `NUMERIC` columns as JS strings —
I designed a test specifically asserting `spent_usd`/`limit_usd` are
numbers, which caught this before Task 4 rather than during it.

**2. What would you change about the process?**
`/rai-story-plan` and `/rai-story-review`'s Step 1 could explicitly prompt
to verify manifest-detected commands work before trusting them for a gate,
rather than discovering it ad hoc per-story. I'd surface this once, not
re-derive it three times across a session (services table via CLAUDE.md,
lint_command, test_command all turned out stale/wrong this session).

**3. Are there improvements for the framework?**
`rai init --detect`'s command-detection heuristic should verify the config
file it implies actually exists at the location it claims the command runs
from (e.g. check for `vitest.config.js` before asserting `npx vitest run`
works), rather than pattern-matching generically across the repo. That's a
`raise-cli` fix, out of reach from here — captured as PAT-S-001 instead so
this repo's own future sessions know not to trust those two specific
detected values.

**4. What are you more capable of now?**
Concrete, reusable knowledge for the rest of this epic: the internal Docker
network/DB connection details (`ioa-governance-platform_ioa-network`,
`db:5432`, `ioa`/`ioa`/`ioa_governance`), a validated manual-verification
recipe (`docker exec -i ... psql <<'SQL'` needs `-i` or it silently no-ops;
insert test data with a clearly-tagged scope value, verify, clean up), and
this repo's actual working test command (`node scripts/test-all.js`, not
the manifest's detected one). S1.2 can reuse all of this directly.

## Patterns Added

- **PAT-S-001** (process): `rai init --detect`'s detected commands need
  verification, not blind trust — this repo's `test_command`/`lint_command`
  are both wrong as detected.
- **PAT-S-002** (technical): `pg` returns `NUMERIC` as strings — parse
  before threshold comparisons.
- **PAT-S-003** (codebase): this codebase's tests mock `pool.query`
  entirely; real-DB manual verification is the only way to catch
  SQL/timezone bugs. Includes the internal DB connection details.
- **PAT-S-004** (architecture): checks that don't fit an existing
  rule-evaluator's shape should be a dedicated mechanism, not forced in
  (ADR-001's reasoning, generalized).
