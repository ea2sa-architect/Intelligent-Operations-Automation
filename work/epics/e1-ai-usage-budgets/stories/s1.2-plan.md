# S1.2 Plan: Enforcement wiring

**Size:** S | **Complexity:** Simple (design skipped per its own gate) | **Date:** 2026-08-03

## Design decision (captured here since no separate design.md)

Check **all** scope dimensions present on the request (`model_id` always,
`user_id`/`service_id`/`workflow_id` if provided) — not just one — since a
budget could be bound to any of them. First `hard`-mode breach found blocks
(403); any `warn`/`breach` under `soft` mode sets `X-IOA-Budget-Warning`
and proceeds. Mirrors the existing `governanceClient`/`X-IOA-Warning`
pattern in the same route exactly (see `inference.test.js`'s `governance
enforcement` describe block).

`spendCheck` is mocked at the module level in tests (default: `ok`,
overridden per test) — the same convention `governanceClient` already
uses in this file. `checkBudget()`'s own internals are S1.1's concern,
already unit-tested; route tests exercise the *wiring*, not the spend math.

## Risks

| Risk | L/I | Mitigation |
|------|:---:|------------|
| Checking 4 scope dimensions serially instead of `Promise.all` adds latency to every inference request | L/L | `Promise.all` from the start, not a later optimization |
| A budget bound to `model_id` gets silently skipped because only `user_id` was checked (the epic design.md's example only showed one scope) | M/M | Task 1's "multiple scopes checked" test explicitly asserts `checkBudget` is called for every non-null dimension, not just `user_id` |
