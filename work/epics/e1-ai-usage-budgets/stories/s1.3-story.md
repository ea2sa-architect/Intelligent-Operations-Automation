# Story: Escalation on breach

## User Story
As a governance admin,
I want a real incident filed when a budget is actually breached by a completed request's cost,
so that overspend gets human attention instead of silently sitting in a `soft`-mode warning header nobody reads.

## Acceptance Criteria

### Scenario: completion pushes a scope over budget — incident filed
```gherkin
Given a budget bound to user_id "team-x", currently under its limit
When PUT /inference/:id completes a request for user_id "team-x" whose cost pushes total spend over the limit
Then escalation-client.createIncident() is called with severity reflecting the budget's mode
And the request still completes normally (this never blocks — S1.2 already gated at POST /)
```

### Scenario: completion stays under budget — no incident
```gherkin
Given the same budget, spend still under limit after this completion
When PUT /inference/:id completes
Then createIncident() is not called
```

### Scenario: no budget bound — unaffected
```gherkin
Given no budget for this scope
When PUT /inference/:id completes
Then no budget check side effects occur (unchanged from today)
```

### Scenario: escalation-service unreachable — fails soft
```gherkin
Given a breach that should escalate
When escalation-service is unreachable
Then the PUT /:id request still succeeds (escalation is fire-and-forget, same convention as every other escalation-client.js in this codebase)
```

## Examples

| mode | breach detected | severity |
|---|---|---|
| hard | yes | high |
| soft | yes | medium |
| either | no | (no incident) |

## Notes

Mirrors `mcp-governance-service/src/lib/escalation-client.js` almost
exactly (`createIncident({title, severity, contextJson})`, fail-soft,
`console.error` on failure, returns `null`) — `ai-inference-service` just
doesn't have one yet. See `design.md`'s "PUT /:id insertion point".
