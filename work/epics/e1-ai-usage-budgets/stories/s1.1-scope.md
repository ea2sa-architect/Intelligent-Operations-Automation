# S1.1 Scope: Budget schema + spend-check

## In scope

- `db/migrations/ai_inference/004_usage_budgets.sql` — new `usage_budgets` table: `id, scope_type, scope_value, period, limit_usd, mode, status, created_at, updated_at`
- `services/ai-inference-service/src/lib/spend-check.js` — `checkBudget({ scopeType, scopeValue })`, computed-on-read `SUM(estimated_cost_usd)` from `inference_requests` scoped by the budget's period, compared against `limit_usd`
- Unit tests covering all 5 scenarios in `s1.1-story.md` (ok / warn / breach / no-budget / period-boundary)

## Out of scope (later stories, not this one)

- Calling `checkBudget()` from `inference.js`'s `POST /` or `PUT /:id` → S1.2
- Blocking a request or honoring `mode` (`soft`/`hard`) → S1.2
- Escalation on breach → S1.3
- Budget CRUD routes/UI → S1.4
- Telemetry chart overlay → S1.5

## Done when

- [ ] `npm run migrate` applies `004_usage_budgets.sql` cleanly against a running Postgres
- [ ] `checkBudget()` returns the documented shape (`{status, budget, spent_usd, limit_usd}`) for all 5 scenarios in `s1.1-story.md`
- [ ] `npx vitest run` passes (new tests included)
- [ ] `npx eslint .` passes
- [ ] `checkBudget()`'s signature matches `design.md`'s Key Contracts exactly — S1.4 will be built against this before S1.2/S1.3 exist
