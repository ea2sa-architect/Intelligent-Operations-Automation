# S1.5 Retrospective: Budget line on Telemetry chart

**Story:** S1.5 | **Epic:** E1 | **Size:** S | **Date:** 2026-08-03
**Time:** Estimated 90 min, actual ~45 min (velocity 2.0x) — low-confidence, same caveat as prior stories.

## What Went Well

- Real visual verification (screenshot, not just "no console errors") caught a genuine bug the first pass would have shipped silently: the reference line existed in the DOM/SVG but was rendered off-screen because Recharts' auto-domain doesn't account for `ReferenceLine` values outside the data's own range.

## What to Improve

- Nothing new — this continued the "actually look at the screenshot" discipline from S1.4.

## Heutagogical Checkpoint

**1. What did you learn?** A component "rendering without errors" and a component "being visible where a user would expect it" are different claims — charting libraries in particular can silently place an element outside the viewport/axis range with zero JS errors. Only a screenshot (not a DOM query, not a console check) catches this class of bug.

**2. What would you change about the process?** Nothing — Task-5-style mandatory visual verification is now a proven pattern across 3 of 4 UI-touching changes this epic (S1.4's Kong/stale-container bugs, S1.5's off-screen reference line).

**3. Are there improvements for the framework?** None new.

**4. What are you more capable of now?** Know to treat any `domain`/axis-scaling prop as a place to check explicitly whenever a chart overlays a value that isn't part of its own underlying data series.

## Patterns Added

- **PAT-S-010** (technical): Recharts YAxis auto-domain doesn't account for ReferenceLine values — must pass an explicit domain when overlaying an out-of-range reference value.
