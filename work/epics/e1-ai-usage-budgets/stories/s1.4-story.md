# Story: Budget admin page

## User Story
As a governance admin,
I want to create, edit, and delete usage budgets from the web UI,
so that I don't have to hand-craft API calls to use the enforcement/escalation that S1.1–S1.3 already built.

## Acceptance Criteria

### Scenario: create a budget
```gherkin
Given the Budget Admin page under Administration
When I fill scope_type/scope_value/period/limit_usd/mode and save
Then a new usage_budgets row is created and appears in the table
```

### Scenario: edit a budget inline
```gherkin
Given an existing budget row
When I edit its limit_usd or mode and save
Then the row updates without a full page reload
```

### Scenario: archive (not hard-delete) a budget
```gherkin
Given an existing active budget
When I delete it via the UI
Then its status becomes 'archived', not a hard row delete — checkBudget()'s
  "WHERE status = 'active'" filter (S1.1) means an archived budget is
  simply never matched again, no enforcement-path changes needed
```

### Scenario: invalid input rejected client- and server-side
```gherkin
Given scope_type/period/mode enums (already enforced at the DB layer by CHECK constraints, S1.1)
When the form is submitted with an invalid combination
Then the API rejects it with 400 before it ever reaches the DB constraint
```

## Notes

Follows `TagAdmin.jsx`'s exact pattern (inline add-row + inline edit-row +
confirm-then-delete), not `WaiverAdmin.jsx`'s (which is decide-only, no
create/edit form) — corrects `design.md`'s original comparison, made
before either file had been read closely for this story.
