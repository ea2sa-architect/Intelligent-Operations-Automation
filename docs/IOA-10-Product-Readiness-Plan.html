Context

Why 1.0 is the right boundary

The capabilities built through EP-305 constitute a complete operational AI governance platform. The next milestone should not be another feature epic.

IOA now has runtime governance and enforcement, approval and containment controls, identity and delegated authorization, continuous assurance, data lineage, behavioral baselining, anomaly detection, and attack-path analysis.

That is enough to define a real product. Continuing to add Phase 4 features before hardening what exists would produce a platform that is wide but fragile — impressive in a demo, unreliable in production. One productization cycle now yields a product that earns trust. Trust is the precondition for every Phase 4 capability being adopted.

Critical

PR-1 — Security Hardening

These items address known security gaps that were explicitly noted as out-of-scope during feature development. All must ship before 1.0.

PR-1 Security Hardening Blocks Ship
1 n8n callback HMAC authentication POST /workflows/analyze/callback/:job_id currently accepts any unauthenticated POST. Add HMAC-SHA256 signature verification using a shared secret with n8n. Known Gap
2 Kong rate limiting on auth and telemetry endpoints Auth endpoints: 20 req/min per IP. Telemetry ingest: 500 req/min per service key. Configure via Kong rate-limiting plugin with --select-tag ioa-governance. Blocker
3 CORS production origin lock-down All services currently allow all origins in development config. Production must enumerate allowed origins explicitly. Verify Kong CORS plugin or Express config per service. Blocker
4 Security response headers Add X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: same-origin via Kong response-transformer or global Express middleware. Gap
5 Startup environment variable validation Each service should validate required env vars at startup and exit with a clear error rather than failing silently at runtime. Prevents misconfigured deployments from accepting traffic. Gap
6 INTERNAL_SERVICE_KEY rotation procedure Document how to rotate the shared key across all services with zero-downtime: add new key, deploy with dual-key acceptance, remove old key. Keep procedure in docs/Security-Operations.md. Doc
Critical

PR-2 — Test Coverage

Test infrastructure was scaffolded early but coverage is minimal. Before 1.0, critical paths must have integration tests that run against real service instances.

PR-2 Test Coverage Blocks Ship
1 Integration test suite for all 6 service APIs Expand existing vitest + supertest scaffolding to cover: all CRUD routes, 401/403 enforcement, validation error shapes, and the require-auth.js middleware conformance. Target: all routes have at least one passing test. Blocker
2 Auth token lifecycle tests Cover: login, session cookie, JWT expiry (60m), write permission enforcement on POST/PUT/PATCH/DELETE, guest read-only enforcement, INTERNAL_SERVICE_KEY bypass path. Blocker
3 Telemetry ingest load test Validate that a batch of 1,000 metric events ingests within 3 seconds. Confirm TimescaleDB compression does not degrade query latency beyond 500ms for 30-day window queries on a populated hypertable. Blocker
4 Migration idempotency verification Run node db/migrate.js twice against a populated database. All migrations must produce identical results on the second run with no errors, duplicates, or constraint violations. Gap
5 SPA golden-path smoke test Using Playwright or equivalent: login → dashboard → governance policy CRUD → MCP server approval → anomaly detection page → lineage chain view. Must run in CI without manual intervention. Gap
Critical

PR-3 — Resilience & Error Handling

The SPA currently crashes to a blank page if a query throws. Several service-to-service calls have no timeout. These are reliability gaps that appear immediately in production.

PR-3 Resilience & Error Handling Blocks Ship
1 React error boundaries on all SPA pages Wrap every top-level page component in an ErrorBoundary that renders a fallback with the error message and a retry button. Currently any thrown query exception produces a blank page. Blocker
2 Service-to-service fetch timeout policy All fire-and-forget fetch() calls (lineage build, control tests, n8n) need a timeout + AbortController. Uncaught hanging connections have caused node process memory growth in testing. Blocker
3 Kong upstream timeout + 502 retry configuration Set connect_timeout, read_timeout, and write_timeout per service in Kong. Configure retries: 2 on 502/503 so a momentary service restart doesn't fail a user request. Gap
4 Graceful DB-unavailable startup If Postgres is not reachable at startup, services should log clearly ("DB unavailable at startup — waiting") rather than accepting traffic and returning opaque 500s. Poll with backoff, not a hard exit. Gap
5 SPA offline / service-down state When the API returns a network error (Kong is down, service is restarting), the SPA should render a clear "Service unavailable" notice rather than empty tables or silent load spinners. Polish
Critical

PR-8 — Deployment Readiness

A Jenkinsfile exists for the SPA only. Six backend services have no automated pipeline. Production deployment is currently a manual process with no rollback procedure.

PR-8 Deployment Readiness Blocks Ship
1 Jenkins pipelines for all 6 backend services Extend the SPA Jenkinsfile pattern: build Docker image, push to registry with a git-sha tag, deploy to target agent. One pipeline per service or a parametrized shared pipeline. Blocker
2 Pinned Docker image versions in production config All docker-compose.yml and K8s manifests must reference git-sha tagged images, not :latest. :latest is acceptable in dev only. Add a pre-deploy check that rejects untagged images. Blocker
3 K8s staging overlay tested end-to-end K8s manifests exist but have not been deployed to a staging environment. Test full stack deploy via kubectl apply -k k8s/staging/. Validate health checks, Kong routing, and DB connectivity in cluster. Gap
4 Production environment variable checklist Document every required env var per service (source, format, rotation frequency). Particularly: JWT_SECRET, INTERNAL_SERVICE_KEY, N8N_API_KEY, DB_URL, CALLBACK_BASE_URL. Doc
5 TLS termination at Kong Configure Kong to terminate TLS for production. Development setup uses plain HTTP on :8000. Production needs a certificate (Let's Encrypt or internal CA) applied to the Kong proxy listener. Blocker
6 Rollback procedure documented and tested For each service: how to revert to the prior image tag. For DB: migration rollback is manual (no down migrations exist) — document which migrations are reversible and what the manual steps are. Doc
Important

PR-4 — Observability

PR-4 Observability 80% Before Launch
1 Structured JSON logging across all services Replace console.error / console.log with structured output: {"level","time","service","correlation_id","msg",...}. All log lines must include correlation_id when available. Gap
2 Request/response logging middleware Log method, path, status code, and duration for every request. Exclude health checks from output. Include x-correlation-id header in every response so callers can trace a request end-to-end. Gap
3 Startup config summary log Each service emits one structured log at startup listing its port, DB schema, and key feature flags. Makes it immediately clear which configuration is active in any environment. Polish
4 Runbook for top 5 failure scenarios Scenarios: DB unavailable, Kong unreachable, n8n webhook timeout, lineage build loop, auth cache miss. Each entry: symptoms, diagnostic commands, remediation steps. Stored in docs/Runbook.md. Doc
5 Key alert thresholds identified Define what should page vs. warn vs. log for: error rate >5%, DB connection exhaustion, telemetry ingest lag >30s, Kong 502 rate >1%, lineage build queue depth >100. Doc
Important

PR-5 — Data Integrity

PR-5 Data Integrity 80% Before Launch
1 Postgres backup cron with tested restore pg_dump to a separate volume on a daily schedule. Test restore to a parallel container. Document restore procedure, target RTO, and backup retention window. Blocker
2 Audit partition auto-management The audit schema uses monthly range partitions. A cron job or startup check must pre-create next month's partition to prevent insert failures. Currently a documented manual step. Gap
3 TimescaleDB 90-day retention policy verification Confirm that add_retention_policy is active on telemetry.metrics and that the policy has fired at least once. Verify compressed chunks are not leaking past the drop window. Gap
4 DB disk space alert threshold Set a monitoring alert when DB volume exceeds 80% capacity. Document expected growth rate based on telemetry ingest volume and compression ratio observed in staging. Doc
5 Migration rollback documentation For each migration that added a column or table: document whether it is safely reversible and what the manual drop/alter is. Migrations with seeded data need special attention — seed re-runs may produce duplicates. Doc
Important

PR-6 — API Completeness

PR-6 API Completeness 80% Before Launch
1 OpenAPI spec completeness across all services The existing Swagger setup covers partial routes. Audit all 6 services for missing route documentation. All routes with a response body must have a schema. The SPA's API Docs page is only as good as the specs behind it. Gap
2 Consistent error response shape All error responses must return {"error": "string"} at minimum. Validation errors add {"field": "string"}. Audit all 500 handlers — some currently return plain strings or Express defaults. Gap
3 Authentication flow documentation end-to-end Document: login flow, JWT claims shape, how INTERNAL_SERVICE_KEY bypasses session auth, the x-correlation-id header threading pattern. Include a sequence diagram. In docs/Authentication.md. Doc
4 API changelog from 1.0 forward Start a CHANGELOG.md at the 1.0 boundary. Any route addition, removal, or breaking change in 1.1+ must be logged here. The absence of a changelog makes upgrades opaque for any integrating party. Doc
Important

PR-7 — UX Polish

PR-7 UX Polish 80% Before Launch
1 Empty states with actionable guidance on all major pages A page that loads zero results should tell the user why and what to do next — not render a blank table. Priority: Anomaly Detection (no alerts yet), Lineage (no telemetry), Assurance (no evidence), Attack Paths (no servers approved). Polish
2 Toast/notification system for mutation outcomes Create/update/delete mutations currently complete silently. Add a lightweight toast notification (success green / error red) confirming the action. Mutations that fail should surface the error message, not drop it. Polish
3 Loading skeletons replacing text "Loading…" Several pages display plain "Loading…" text while queries are in-flight. Replace with skeleton placeholders that match the shape of the content — reduces perceived latency and is more professional. Polish
4 SPA code splitting — lazy-load admin pages Current bundle is 1,047 KB (285 KB gzip). Admin pages (Prompt Registry, Control Tests, API Docs, etc.) are rarely used by most users. Lazy-load them with React.lazy() to reduce initial load by ~30%. Polish
5 404 route and application error page Currently an unmatched path renders a blank page. Add a <Route path="*"> that renders a minimal 404 with navigation back to the dashboard. Gap
6 Mobile layout audit The sidebar collapses on mobile, but several pages have wide tables and the SVG DAG visualizer (Lineage, Attack Paths) doesn't constrain correctly on narrow viewports. Wrap wide content in overflow-x: auto containers. Polish

What 1.1 looks like

Phase 4 epics are explicitly deferred, not cancelled. They become the foundation of the 1.1 cycle, which begins the moment 1.0 ships.

EP-401
Framework Crosswalk — Map existing IOA policies to NIST AI RMF Govern/Map/Measure/Manage and OWASP GenAI top-10. Exportable compliance evidence packages (JSON + CSV). Dashboard with per-framework coverage and gap count.
EP-402
Third-Party Risk — Extend publisher registry with contract status, security assessment dates, hosting regions, and subprocessors. SBOM and component provenance. Supply-chain risk score per MCP server. Violation on unsigned or stale dependencies.
EP-403
Asset Ownership — Business, technical, risk, and data owners per asset. Quorum approval support (parallel + sequential stages). Orphaned asset detection with automatic escalation. Slack/email notification integration.
EP-404
Risk-Adjusted ROI — Derive AI usage cost from telemetry token counts × provider pricing. Risk/value quadrant matrix. Replace the ROI placeholder with a live data view. Per-workflow recommendations: Scale / Control & Monitor / Retire / Deprioritize.
Auth 1.1
Fine-grained Permissions + SSO — Named per-action permissions (approve_mcp_server, create_waiver, etc.) replacing the coarse read/write model. SAML or OIDC provider federation for enterprise single sign-on.
